# 🗺️ Roadmap

Where Auditarr is heading. Each line starts with its status: 🟢 **done** and in the app today · 🟡 **in progress** right now · 🔴 **not started** · 🙋 **waiting on the owner** (a step only the project owner can do, like a submission). The first 🔴 in each list is what's next. (The short codes like `T1`/`U1` are just internal labels.)

The current focus: make the app **trustworthy to run** (a real test harness) and **easy to read** for someone who isn't a developer.

## 🗂️ How we track work (added 2026-11-12)

- **This file** is the big picture: phases, what is done, what is next, in plain words.
- **The board** across both apps: https://github.com/users/chrizantoz/projects/1 (cards grouped by status, app, area or phase).
- **GitHub Issues** is the inbox and the day-to-day list. Anything found along the way becomes one issue with one label: `bug`, `bot` (the test bots), `feature`, `ux` (friendlier wording, navigation, flow), `design` (look and feel), `idea`, `owner-step`. Milestones match the phases here.
- **Rule:** an idea is written down the moment it comes up, as an issue, not remembered. When an issue ships, this file gets its line and the issue closes.
- **GitHub's own bots count too (added 2026-11-12).** Code scanning (CodeQL), Dependabot and secret scanning alerts become issues labelled `security`, opened by the `alerts` workflow every morning (one issue per alert, never twice). Each one is fixed with a test, or dismissed on GitHub with a written reason; never left open without a look.
- **Every bug teaches something.** When a bug is fixed, its lesson goes under *What bugs taught us* below: the pattern behind it, the guard that now stops it (a test or a bot world), and any idea it gave for later (filed as an `idea` issue).

## 🚧 Now: solid testing + a friendlier interface

🧪 **Testing — proving it does the right thing**
- 🟢 **T1** A read-only mode (`READ_ONLY=1`): every change it would send to an arr, Bazarr or Plex is blocked and counted instead, so test runs can't touch anything real.
- 🟢 **T2** Update-testing compares findings check-by-check, not just by the total count.
- 🟢 **T3** Code linting in CI.
- 🟢 **T4** Fake media with known defects (built with ffmpeg) that the detectors must catch in CI.
- 🟢 **T5** "Tonight's plan": a panel and API showing exactly what the night's automatic actions would do; the self-test confirms the planners run.
- 🟢 **T6** Backup proof: a nightly integrity check of the newest backup, shown in History.
- 🟢 **T7** Failure drill: a test run with Bazarr / Plex / an arr switched off must still finish and report "degraded" rather than crash.
- 🟢 **T8** A real-browser test (Playwright) at phone and desktop width that fails if raw codes or setting names leak into the normal view, with screenshots kept as CI artifacts.

🙂 **Usability — making it readable**
- 🟢 **U1** Plain names for every check and severity; codes moved to tooltips.
- 🟢 **U2** A human sentence first on every finding, technical detail folded away.
- 🟢 **U3** Verb buttons ("Download a better copy", "Make subtitles"…), old names kept as tooltips; an Undo toast after any file move.
- 🟢 **U4** A simple view by default (just "Needs you" + "Done overnight"); low-priority groups, Live and History tucked behind an Advanced switch.
- 🟢 **U5** In-page help: a "?" on each section opens the matching part of the user guide.
- 🟢 **U6** Settings shown as grouped switches and sliders with plain sentences; setting names only in Advanced.
- 🟢 **U7** A visual identity (first pass, 2026-11-11: teal accent, magnifier-check logo and favicon, light theme via system preference or the ◐ toggle, themed chips/buttons/confirms; icon.png for the Unraid template). Polish continues with the screenshot baselines. Original brief: a visual identity: give Auditarr its own look, the way Sonarr/Radarr/Bazarr/Seerr each have one — an accent colour, a logo/icon, light and dark themes, and consistent chips and buttons; the plain-language rules and the test bots' selectors stay intact.

## 🤖 Now: the self-testing bots (same rule — checked means done)

- 🟢 **Q1** A fake arr stack in CI: mock Sonarr/Radarr/Bazarr + fake media + the real app, with the browser bot clicking real buttons that hit the real API (trash → Undo → restored, re-download → arr receives the command, AI subtitles → job queued).
- 🟢 **Q2** Plain-language guardrails: every check's sentence and every button label must be free of codes and arr jargon, 30 words or fewer, and end in a full stop — enforced in CI.
- 🟢 **Q3** Living test data: a nightly sanitised snapshot from a real library, plus hand-made edge cases (empty library, zero findings, a 2000-finding show, every service down, API errors).
- 🟢 **Q4** A contract test tying the UI and API together: every button the UI offers is accepted by the backend, and every finding the API returns renders as a row.
- 🟢 **Q5** Accessibility scan (contrast, labels, focus order) in the browser run; fails on serious issues.
- 🟢 **Q6** Visual-regression check: baseline screenshots (in `uibot/baseline/`, taken from CI) that fail on a >1 % pixel change at phone and desktop width; refresh them on purpose after a visual change.
- 🟢 **Q7** "Monkey" run: 60 seconds of random clicking with no JavaScript errors, and every save preceded by a confirm box.
- 🟢 **Q8** Rotating failure drill: a different service down each week (all / Bazarr / Plex / Whisparr by week number). The slow-service variant is split out as Q9.
- 🟢 **Q9** (2026-11-11) Slow-service drill: `auditarr-deploy.sh drill 4` puts Sonarr behind a 200 s latency proxy (a throwaway python container); the staged run must finish within 25 min, report Sonarr degraded and write nothing. Part of the weekly rotation.

## 📚 What bugs taught us (added 2026-11-12)

Each line: the pattern → the guard that stops it now → the idea it left for later.

- **A file's name can lie about what it is** (#32, #35: MP4 files named .mkv failed every night). → The file's first bytes decide, and MP4_IN_MKV gets its own finding and *Rewrap the file* (F35). → 💡 Check the other way round too (.mp4/.avi names on Matroska files) and say so in the same finding.
- **An automatic fix that fails must back off, not retry every pass** (#35: 88 errors a day from 8 files). → Failed default-flag edits wait a day unless the file changed. → #40 (2026-11-13): one back-off for all five nightly fixes (1, 3, 7 days, then give up until the file changes); Today lists what it gave up on.
- **A button must show that it worked, until the job is done** (#37, #38). → *Being fixed now* box; AI subtitles trigger a timing re-check; #41 (2026-11-12): Refresh in Plex and Rescan the folder look again until the file shows up or say it did not. Every other fix already checks itself before it reports done.
- **A fix that changed nothing must not be offered again** (#48: five episodes re-timed 3-5 times each; Bazarr rewrote the file, the numbers stayed the same). → A file Bazarr already re-timed offers AI subtitles instead, and the server refuses a second re-time. → 💡 Every fix button compares the check before and after; "no change" retires that button for the file (#49).
- **Another app's choice must be checked, not trusted** (#51: Bazarr made AI subtitles from a Portuguese or English dub track because its list of a file's audio languages has no fixed order). → Auditarr compares the track Bazarr names with the original language, and uses the right track itself when they differ. → 💡 Report it upstream to Bazarr: in the translate case, pick the original-language track and send that same stream (#52).
- **Startup must not wait on another app** (2026-11-13: the one-time redo asked Sonarr about every title before the page was up, and the update script reported "failed to start"). → Slow repairs run in the background after the page is up; a regression check. → 💡 The page bot measures time-to-first-answer after a restart.
- **Two paths into one queue need one door** (#50: a startup repair and the restart re-queue both queued the same 23 jobs). → The queue refuses a job id that is already waiting; a regression case. → 💡 The Actions tab warns when the same job runs twice within an hour.
- **One noisy sample is not a verdict** (#48: 8 of 23 timing rows were one odd sample out of three). → A second look next to the odd sample; an unconfirmed drift closes as "not sure". → 💡 Show the samples on the row, so a person can see why it says drift.
- **A clean-up must only close what it checked** (#46: every audit closed every subtitle-timing row, because the audit never makes one). → Rows made by a background check stay until that check, a fix or a new file closes them; a full-stack test plants one and runs a real audit. → #47 (2026-11-13): `ROW_MAKER` + `sweep_may_close()`; `tests/row_owners.py` checks every place that closes rows (it caught four kinds missing from its own first list).
- **A test that runs one case a day can break quietly** (2026-11-12, seen in Dedupearr). → `mutation_check.py anchors` checks every mutant's line on every CI run, in both apps.
- **Each arr has its own shapes** (#27, #28, #29: Sportarr files, ids and languages). → Sportarr cases in the regression corpus. → 💡 A small fixture per supported arr in the page bot, not only Sonarr/Radarr.
- **A page opened straight on a tab can run before its data** (#34). → The `deeplink` bot world. → 💡 The bot opens every tab directly, not only #setup.
- **A status line must read the same data as the check behind it** (#31: "a self-test is failing" while all passed). → Today reads the self-test result itself. → 💡 Lint: every status sentence names the field it comes from.
- **Same name, two meanings breaks things quietly** (2026-11-12: a new `INFLIGHT` would have replaced the deploy's request counter). → Caught by review; the busy marks use `PRESSING`. → 💡 A lint that refuses a second top-level assignment of the same name in audit.py.
